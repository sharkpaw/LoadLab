# AGENTS.md

Guidance for AI coding agents (and humans) working on LoadLab. Keep it short and accurate; update it when conventions change.

## What this is

A self-hosted load-testing platform on top of [k6](https://github.com/grafana/k6): a React dashboard, a Fastify API (REST + SSE + MCP), and workers that run k6. Users model **workflows** (user journeys), combine them into **test plans** (mix + load profile + thresholds) and start **runs**. Everything runs with Docker Compose (Postgres + Redis + api + worker).

## Layout

| Path | What lives there |
|---|---|
| `server/src/api.ts` | API entry: Fastify, security headers, static dashboard, scheduler & janitor loops |
| `server/src/routes.ts` | REST routes + Better Auth handler mount + `/api/runs/:id/live` (SSE) |
| `server/src/mcp.ts` | MCP server (Streamable HTTP, stateless). Tools call the same services as REST |
| `server/src/lib/services.ts` | **All business logic** (sites, workflows, plans, runs, system). REST and MCP are thin wrappers |
| `server/src/lib/auth.ts`, `lib/mailer.ts`, `cli.ts` | Better Auth setup (2FA, rate limits, reset mail), optional SMTP with log fallback, admin CLI |
| `server/src/lib/compiler.ts` | Plan + workflows → k6 runner config (profiles → scenarios, includes, host allowlist, limits) |
| `server/src/lib/schemas.ts` | Zod schemas for the workflow DSL and plan config, plus the DSL docs shown to users/LLMs |
| `server/src/db/schema.ts` | Drizzle schema — **single source of truth** for the database (app + Better Auth tables) |
| `server/migrations/` | SQL generated by drizzle-kit. Never edit by hand |
| `server/src/worker.ts`, `worker/executor.ts` | Claims queued runs (`FOR UPDATE SKIP LOCKED`), spawns k6, streams metrics, auto-stop/capacity |
| `server/src/worker/aggregator.ts` | Parses k6 JSON output (via a FIFO) into per-second buckets and per-step histograms |
| `server/k6/runner.js` | Generic k6 script that **interprets** the workflow DSL. Runs inside k6 (Sobek JS), not Node/Bun: only `k6/*` imports |
| `web/src/` | React 19 + Vite + Tailwind 4 dashboard. `lib/i18n.tsx` + `locales/tr.ts` for translations |
| `docker-compose.yml` | Coolify-compatible stack (`expose`, `SERVICE_*` magic secrets). `docker-compose.local.yml` adds ports, `docker-compose.ci.yml` adds a target site |

## Commands

```bash
# server (Bun runs TypeScript directly)
cd server && bun install
bun run typecheck            # tsc --noEmit
bun run test                 # unit tests (bun test)
bun run db:generate --name x # after editing src/db/schema.ts
bun run db:check

# web
cd web && bun install
bun run dev                  # http://localhost:5173, proxies /api and /mcp to :8080
bun run build                # tsc + vite build
bun run i18n:check           # every t()/msg() string must have a Turkish entry

# admin CLI (inside the api container on a server)
bun src/cli.ts help         # users, reset-password, disable-2fa, revoke-sessions, create-user, delete-user

# whole stack
cp .env.example .env && docker compose up -d --build     # http://localhost:8080
# e2e smoke test against a running stack with docker-compose.ci.yml
BASE_URL=http://localhost:8080 TARGET_URL=http://target ADMIN_PASSWORD=… bun server/test/e2e/smoke.ts
```

CI (`.github/workflows/ci.yml`) runs all of the above on every push and PR, then boots the stack in Docker and runs the smoke test.

## Conventions

- **Language:** code, comments, logs, API errors and docs are English. UI text is English source strings wrapped in `t('…')` (or `msg('…')` inside constant arrays, translated at render). Add the Turkish entry to `web/src/locales/tr.ts` in the same change.
- **Server-generated text** shown in the UI (stop reasons, warnings, breach reasons) is English; `tServer()` in `web/src/lib/i18n.tsx` translates the known patterns. If you change one of those strings on the server, update the pattern too.
- **Database:** change `src/db/schema.ts`, then generate a migration and commit both. Columns are camelCase in TS and snake_case in SQL (`casing: 'snake_case'`). In correlated subqueries written with `sql\`\`` on single-table selects, qualify the outer column explicitly (`"sites"."id"`): Drizzle does not qualify columns there.
- **Business logic** goes in `services.ts` so REST and MCP behave the same. Throw `HttpError(status, message, details?)` for user-facing errors.
- **Style:** TypeScript strict, ESM, 2-space indent, single quotes, no default exports on the server. Match the surrounding code; keep comments short and about *why*.

## Safety rules (do not weaken)

- A test may only send requests to its site's `baseUrl` host and `allowedHosts`. This is enforced at compile time (`checkStaticHosts`) **and** at runtime in `runner.js` (`hostAllowed`). Keep both.
- MCP creates **drafts** only; starting a test over MCP is gated by `MCP_ALLOW_RUN` (default off). MCP may edit drafts, not active workflows/plans.
- Respect `MAX_VUS`, `MAX_RATE`, `MAX_DURATION_SEC` in `buildScenario`.
- Never log or return secrets: API keys are stored as SHA-256 hashes; Better Auth handles passwords.
- Public sign-up stays disabled (`/api/auth/sign-up/*` returns 403); users are added by signed-in users or the CLI.
- Revoke sessions through Better Auth (`(await auth.$context).internalAdapter.deleteUserSessions`), never by deleting rows: sessions are cached in Redis.
- Password-reset mail must not reveal whether an account exists; `sendResetPassword` is fire-and-forget on purpose.
